# ADR-002: 产品定位 — AI 助手团队而非 DSH 桌面壳

- 状态: Accepted
- 日期: 2026-08-14
- 决策者: 柳俊明
- 参考: Grok Bot 产品分析 + DSH 社区痛点调研

## 背景

DeepSeek Harness 77k+ stars，但：
- 99% 的普通人卡在「装完不会用」
- 命令行、plugin、preset、profile、patch — 全是技术黑话
- 社区已经有 5+ 个薄壳桌面端，全是 iframe 套 DSH Web UI，无差异化

Grok Bot 验证了「AI 同事」的产品心智，但：
- $200/月太贵
- 云端运行，数据不在本地
- 只支持 Grok 模型

中间有空白：**普通人能用的、便宜的、本地的 Agent 桌面端**。

## 决策

**产品定位：鲸团 — 你的第一个 AI 助手团队**

- 不是"DSH 桌面客户端" — 用户不关心 DSH 是什么
- 不是"AI 聊天机器人" — 太泛，没有差异化
- 是"你的 AI 团队" — 有具体的助手角色，能真干活

**核心叙事：**
- 打开 App 就有 4 个 AI 同事在等你
- 小文写文案，阿码写代码，小研做调研，小创打杂
- 给它们派活，它们自己干，完了通知你
- 数据都在你电脑上，用多少花多少

## 为什么是这个定位

### 1. 降低认知门槛
"选个 preset 配个 profile" vs "找小文帮你写" — 后者不需要学习成本。

### 2. 差异化竞争
- 社区那些壳："DSH 桌面版，功能跟网页版一样" — 没有理由下载
- 我们："你的 AI 团队，双击就能用" — 有明确的价值主张

### 3. 可扩展性
今天 4 个助手，以后可以加更多，也可以让用户自定义。
从"工具"变成"平台"，天花板更高。

### 4. 对齐 Grok Bot 的已验证心智
Grok Bot 用"AI 同事"的定位已经验证了市场接受度。
我们做的是：更便宜、本地、开源、多模型的版本。

## 具体落地

### 产品层
- 首页是「我的 AI 团队」，不是空白聊天框
- 每个助手有头像、名字、一句话描述
- 点助手 → 进入对话，上下文已经配好了

### 技术层
- 每个助手 = 一个 DSH profile
- 预设助手 = 预配置的 DSH profile（模式 + 插件 + 系统提示词）
- 切换助手 = 切换 DSH profile
- DSH 是引擎，用户看不到引擎

### 文案层
- 不说「preset」说「助手」
- 不说「plugin」说「技能」
- 不说「subagent」说「团队成员」
- 不说「approve」说「帮你看看」

## 后果

### 正面
- 有清晰的产品定位，不是"又一个壳"
- 面向更大的市场（下沉用户 vs 开发者）
- 可扩展性强，从 4 个助手到助手市场
- 故事性强，适合传播

### 负面
- 需要做更多的产品设计（不只是技术封装）
- 预设助手的质量决定产品体验
- 需要持续维护预设配置（DSH 更新可能需要适配）
- 自研 UI 工作量比纯 iframe 壳大

### 风险与对策
| 风险 | 对策 |
|------|------|
| 预设助手效果不好 | MVP 先做 2-3 个核心场景，做深不做多 |
| 用户想要更多自定义 | v0.2 加自定义助手功能 |
| DSH 更新破坏预设 | 锁定 DSH 版本，每次升级前测试 |
