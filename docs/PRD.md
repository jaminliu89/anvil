## 1. 产品定位

**一句话**：打开就有 AI 同事在等你，不用命令行，不用装环境，给它派活它自己干。

**目标用户**：
- 自媒体人 / 一人工作室 / 小老板
- 想用 AI Agent 但不会用命令行的人
- 觉得 ChatGPT 只会聊天、干不了真活的人
- 嫌 Claude Code / Codex 太贵、太复杂的人

**核心价值**：
- **零门槛**：双击安装，下一步下一步，不用装 Node.js，不用敲命令
- **有人味**：不是聊天窗口，是你的 AI 团队——文案、代码、研究各有专人
- **真干活**：DSH 引擎驱动，能写代码、能搜资料、能读文件、能跑命令
- **省钱**：按用量付费，不用 $200/月，一天几毛到几块钱
- **全本地**：数据存你自己电脑上，不上传任何第三方

---

## 2. 为什么是现在

- DeepSeek Harness 77k+ stars，GitHub 史上最快涨星项目，关注度爆炸
- 但 99% 的人卡在「装完不会用」—— 命令行、插件、preset、patch，全是技术黑话
- Grok Bot 把 Agent 包装成「AI 同事」验证了产品心智，但 $200/月太贵且云端运行
- 中间有个巨大的空白：**普通人能用的、便宜的、本地的 Agent 桌面端**

我们做的不是另一个 DSH 壳，是把 DSH 的技术能力翻译成普通人能用的产品。

## 3. 核心功能

### 3.1 我的 AI 团队（首页）

打开 App 第一眼看到的不是空白聊天框，是你的 AI 团队：

| 助手 | 一句话描述 | 对应 DSH 模式 |
|------|-----------|--------------|
| 小文 | 文案写手——写小红书、公众号、口播稿、脚本 | 标准模式 + 写作技能包 |
| 阿码 | 程序员——写代码、改 bug、代码审查 | PTC 模式 + 代码工具链 |
| 小研 | 研究员——搜资料、做调研、写报告 | 标准模式 + 搜索 + 网页阅读 |
| 小创 | 打杂能手——什么都能试试，你可以自定义 | 创造模式 + 全部插件 |

每个助手有头像、有简介、有擅长领域。点一下就开聊，不用选模型不用配工具。

### 3.2 对话即工作

- 跟助手聊天，它用工具自己干活
- 右侧实时显示「正在做什么」—— 搜了什么、读了什么文件、执行了什么命令
- 需要你拿主意的时候，停下来等你审批
- 干完了弹通知，不用盯着屏幕

### 3.3 后台常驻

- 关窗口最小化到托盘，不退出
- 助手继续干活，完了系统通知你
- 托盘菜单：快速查看正在进行的任务、快速唤起窗口、退出

### 3.4 一次配置，终身使用

- 首次启动 3 步走：选语言 → 填 API key → 选默认助手
- 不用懂什么是 preset、bundle、patch、profile
- 以后想换模型 / 加插件，在设置里一键切换

## 5. 技术规格

### 5.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 桌面壳 | Tauri v2 (Rust) | 不用 Electron，体积小启动快 |
| 前端 | Vue 3 + TypeScript + Vite | 生态成熟，开发效率高 |
| UI | 自研组件 + 部分 naive-ui | Hermes 风格，扁平极简 |
| 状态 | Pinia | Vue 3 官方推荐 |
| 引擎 | DeepSeek Harness (Node.js) | 77k+ stars，一切皆插件 |
| 进程管理 | Rust sidecar manager | DSH 作为子进程，生命周期由 Rust 管 |
| 存储 | IndexedDB (前端) + DSH 自带持久化 | 会话用 DSH 原生存储，配置存前端 |
| 系统集成 | Tauri 插件（tray / notification / autostart / global-shortcut） | |

### 5.3 数据流

1. 用户点击「小研，帮我调研一下竞品」
2. 前端 → IPC → Rust：发送消息给指定助手
3. Rust → DSH stdin：JSON-RPC 消息（带上 assistant preset）
4. DSH → DeepSeek API：流式生成 + 工具调用
5. DSH stdout → Rust → 前端事件：实时推送 delta + 工具调用状态
6. 前端：消息流追加 + 干活轨迹面板更新
7. DSH 完成 → Rust → 前端 end 事件 + 系统通知

## 6. 设计原则

### 6.1 视觉风格
- 扁平、极简、无多余装饰
- 深色为主（对齐 DSH 官方调性，但更柔和）
- 助手卡片用头像 + 名字 + 一句话描述，像联系人列表不像功能菜单
- 「干活轨迹」用时间线样式，实时追加

### 6.2 交互原则
- **少即是多**：首页不超过 5 个可点击元素
- **默认即最优**：预设助手就是最佳配置，不用调
- **进度可见**：AI 在干什么用户要能看到，不是黑盒
- **不打扰**：后台运行时只有必要时才弹通知

### 6.3 文案原则
- 不用技术术语：不说「preset」说「助手」，不说「plugin」说「技能」，不说「approve」说「帮你看看」
- 像人说话，不像说明书
- 出错了说人话，不给 error code

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| DSH 还在开发者预览，破坏性更新 | 高 | 锁定 DSH 版本，更新前测试 |
| 内嵌 Node.js 增大包体积 | 中 | 用精简版 Node，或用 Rust 侧直接调 HTTP API（但丢了插件能力） |
| DSH 官方以后出自己的桌面端 | 中 | 我们的差异化是「下沉市场 + AI 团队心智」，官方做的是给开发者的工具 |
| 流式输出的 stdio 协议不稳定 | 中 | 先用 DSH 官方的 JSON-RPC 协议，必要时回退到 HTTP API |
| 苹果审核 / 公证问题 | 低 | Developer ID 签名 + 公证，走 Tauri 官方打包流程 |
