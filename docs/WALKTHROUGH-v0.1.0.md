### 遗留风险
1. **内嵌 Node runtime**：当前依赖系统 npx，用户没装 Node 就用不了。这是最大的发布阻断项。
2. **单实例缺失**：重复打开会启动多个 DSH 进程。
3. **API key 校验**：只有格式校验，没有实际调用验证。
4. **工作区 UI**：只有 store 层，没有可视化入口。

## 二、SA 视角 · 架构与代码质量

### 架构分层

```
┌─────────────────────────────────────┐
│  前端壳层 (Vue 3 + TS)              │
│  ├─ 4 个视图（team/chat/settings/onboarding）
│  ├─ 4 个 store（team/dsh/settings/workspace）
│  └─ services（dsh 封装 + 事件监听）
├─────────────────────────────────────┤
│  Tauri Bridge                       │
│  └─ 6 个自定义 commands + 8 个 plugin
├─────────────────────────────────────┤
│  Rust 侧 (Tauri v2)                 │
│  ├─ dsh/ 进程管理器（状态机 + 健康检查）
│  ├─ tray.rs 系统托盘
│  ├─ shortcuts.rs 全局快捷键
│  └─ system_commands.rs 窗口控制
├─────────────────────────────────────┤
│  DSH Sidecar (Node.js)              │
│  └─ npx @deepseek-ai/dsh web        │
└─────────────────────────────────────┘
```

### 技术债务清单

| 级别 | 问题 | 建议 |
|------|------|------|
| 🔴 高 | 依赖系统 Node，非自包含 | 内嵌 Node binary + DSH bundle |
| 🟡 中 | 崩溃自重启未实现 | 加指数退避 + 最大重试 |
| 🟡 中 | 单实例插件未启用 | 解决 API 兼容性问题 |
| 🟡 中 | 无测试覆盖 | 加单元测试（store/工具函数） |
| 🟢 低 | DSH 启动超时固定 30s | 可配置化 |
| 🟢 低 | settings store 字段多，加载慢 | 按需加载 |

### 包体积现状
- App 本体：15 MB（Tauri + Rust）
- DMG：5.2 MB（压缩后）
- 不含 DSH + Node runtime（约 100MB+）

### 代码质量
- TypeScript 严格模式，0 类型错误
- Rust 0 编译错误，2 个 unused warning
- 模块化清晰，按职责分文件
- 本地持久化统一走 Tauri store plugin

## 三、UX 视角 · 用户体验

### 视觉风格
- 深色主题，扁平设计，对齐 Hermes desktop 调性
- 琥珀色（#f59e0b）作为主色，温和不刺眼
- 圆角 8px，间距系统 4px 基准
- 无 emoji 装饰（按钮/标题纯文字），仅助手头像用 emoji

### 交互流程

**首启动**
- 进度条式引导，3 步走完
- API key 输入有格式校验 + 官方平台链接
- 最后一步选默认助手，卡片式选择，点击即完成

**日常使用**
- 团队首页一眼看到所有助手
- 点击卡片直接进入对话
- 关窗不退出，后台驻留
- Option+Space 随时唤起

**问题点**
1. 首次启动 DSH 等待时间长（约 5-10s），加载页只有 spinner，缺乏预期管理
2. 助手卡片 hover 态不够明显
3. 设置页没有分组折叠，内容偏长
4. 没有空状态引导（首次进入团队首页的 tips）
